Why these rules exist

00 · context

A two-year-delayed UI overhaul shipped in November 2025 and was met with the worst reception in the genre's history. The complaint pattern was not "we don't like change." It was specific, technical, and — for a desktop product — predictable. We use it as a reference set, not a target to dunk on. Every principle below maps to one of these failure modes.

The PC felt like a port

Reviewers and 12,000-hour veterans converged on the same diagnosis: oversized buttons, inflated padding, fewer rows visible per screen, and console-shaped panels that left desktop users hunting for information that used to sit in a single glance.

GameSpot · Operation Sports · Steam community, Nov 2025

Tiles replaced tables

The new shell turned dense tables into "tiles" that opened into "cards" with the rest. Players described basic management — checking a scout report, comparing two transfer targets — as "a frustrating scavenger hunt." A click is a tax. Every extra one compounds.

Operation Sports review · Galaxus, Nov 2025

Predictability collapsed

Identical-looking controls behaved differently depending on context — sometimes opening a drawer, sometimes navigating away. Once trust in interaction goes, every click becomes a guess. For a sim built around hundreds of clicks per session, that is fatal.

Steam discussion threads, Oct–Nov 2025

The ten principles

01–10 · rules

Each principle is a rule, a rationale, and a "what we saw fail" lesson. The do / don't pair shows the same data with our system on the left and the failure mode on the right.

01

Density is identity, not a debt to repay

Layout

Every screen ships at least as much usable information as the bar set by 2024-era management sims. We earn space by adding signal, not by removing rows.

A squad screen should show 20–25 players visible without scrolling at 1080p. Stat tiles must hold real numbers, not labels. White space is for grouping, not for breathing room — analysts compare; comparisons need adjacency.

Failure mode observed "Too much empty space, oversized buttons, and far less information on screen" was the single most-repeated complaint about FM26's launch shell.

02

Zero clicks for the obvious answer

Information arch.

If a manager opens a screen with a question in mind, the answer is on that screen — not behind a tap, hover, or expand.

Squad → form, fitness, morale visible inline. Match → goal scorers in the headline. Transfers → asking price on the row, not in a drawer. Tooltips clarify; they never reveal primary data.

Failure mode observed FM26 community feedback consistently flagged that "tables and windows reveal fewer key figures than before and hide important details behind tooltips or icons."

03

Tables stay tables. Don't tile-ify dense data.

Components

When the data is comparative — squad, league, transfer market, scouting — it's a table. Sortable columns, fixed headers, alignable numerals, keyboard arrow navigation.

Tiles and cards are for dashboard summaries, where each item is independent. The moment a user wants to compare two rows, a card layout becomes a usability failure: their eyes can't scan the columns, and sort/filter loses meaning.

Failure mode observed Veteran players described navigating a tile-and-card squad list as "driving a car with a square steering wheel." The shape of the data changed; the task did not.

04

A control does the same thing every time

Interaction

Identical-looking elements behave identically. Primary buttons commit. Tertiary buttons navigate. Drawers slide; pages replace. The visual style telegraphs the outcome before the click.

We codify this in three button shapes only: primary (filled green), secondary (outlined), ghost (text-only). Filled buttons never navigate. Ghost buttons never commit irreversible actions. Same icon = same affordance, system-wide.

Failure mode observed "Sometimes when I press this... this happens — but when I press the same button here... something else happens." The single most fatal failure: trust in the cursor.

05

Sized for a cursor, not a thumb

Sizing

Default control height is 28px. Compact rows hit 24px. Primary actions can rise to 32–36px. Anything taller than 40px is reserved for the few moments a click should feel weighty — sign player, end season, sack.

A mouse hits a 24px target reliably. A 56px button on a desktop screen wastes six rows of squad data per occurrence. We design the screen first, then size the controls to fit it — never the inverse.

Failure mode observed The collective verdict on FM26's control sizing was that the PC build felt like "a poorly ported console game." Touch-tier hit targets carried over to mouse-only contexts.

06

Keyboard search is the fastest navigation

Navigation

A global command palette (⌘K / Ctrl K) jumps to any screen, player, club, or action in two keystrokes. Power users never click through menus.

The palette indexes screens, entities (players, clubs, staff, leagues), actions ("offer contract to…", "set instructions for…"), and recent items. Navigation depth becomes a non-issue when the path is one search away.

Failure mode observed FM26 attempted this with a new search bar that "delivers more results, depth and assistance" — a sound principle let down by deeper menus everywhere else, so power users still bounced through 4–5 panels for routine tasks.

07

No hidden primary data behind hover or icons

Information arch.

A column showing only an icon (☆, ⚠, ⚽) is a column that lost. Show the value next to the glyph, or omit the column. Tooltips supplement; they don't substitute.

If a manager wants to know "who's tired?", the row shows 87% — not a battery icon. The icon can ride alongside as visual sort, but the number is non-negotiable. This is what "more contextual data served earlier" actually looks like in practice.

Failure mode observed FM26's redesign moved important figures into icon-only columns and tooltips, requiring hover or click to see numerical context that the table previously showed inline.

08

Views are the user's, not the designer's

Customization

Every dense table ships a column picker, a sort memory, and saved view presets. Filters persist between sessions. Skin support is a launch feature, not a roadmap item.

Football managers play 200+ hours per save. They develop personal rituals — "the columns I check before a transfer window". The system honors those: three default views (General, Tactical, Financial) ship out of the box, plus unlimited user presets stored locally.

Failure mode observed The lack of skin/customization support at FM26 launch left the community without their usual recovery path. "We can't even fix the problems ourselves" became a refrain.

09

Honest at every resolution from 1366 to 4K

Responsive

Layouts adapt by tier, not by free-flow scaling. Critical actions are reachable at every supported resolution. UI scale slider exposes 90 / 100 / 110 / 125% as user preference — the design ships fluent at all four.

Three tiers: compact (1366–1599), standard (1600–2199), wide (2200+). At compact, secondary columns fold first; primary actions never. We test at 1366×768 as a CI gate, not a "nice to have."

Failure mode observed FM26 had documented bugs at 1366×768 — overlapping menus, contract options cut off — and 2K blurriness, which broke fundamental tasks for laptop and modern-monitor users alike.

10

Sub-100ms perceived response, no exceptions

Performance

A click registers, a hover paints, a sort completes inside 100ms of perceived time — typically under 50ms. Animation never delays interaction; if a transition would gate input, it gets cut.

Concrete budgets: 16ms per frame, 50ms for click feedback paint, 100ms for sort/filter on 50,000-row tables, 1 frame for tab switches. Easing curves are short (180ms max) and never block. Loading spinners are admissions of failure, not features.

Failure mode observed "Significant UI latency, stuttering, sluggish scrolls, slow menu transitions" — the most quotable phrase from the FM26 launch was that the interface "felt laggy." For a sim that lives in menus, this becomes a catastrophic failure.
