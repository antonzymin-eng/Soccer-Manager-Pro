Question one

What should be a skill

Candidates ranked by how often the repo's own history shows the work being repeated. A skill earns its place by being triggered, so each card names the trigger, not just the behavior. Downloads give you a ready SKILL.md scaffold.

.claude/skills/landing-record/

The landing ritual

Four files move together at the end of every substantive change, in a specific format, and the set is easy to under-do under time pressure.

Trigger
A code or spec change is about to be committed — before the commit, not after.
Context
Header-entry format and the "prior entry below" chaining rule; when src/CLAUDE.md takes a version bump; file-manifest.md row shape; whether the change files an ERR-; whether SNAPSHOT_SCHEMA_VERSION moved.
Evidence
58 commits touch CLAUDE.md; of those, 37 also touch src/CLAUDE.md, 34 file-manifest.md, 18 spec-error-log.md.

.claude/skills/err-file/

File an ERR without a collision

The repo has already been bitten by this exact failure: three design supplements proposed ERR- ids that had already been filed the same day, because nothing cross-checks a proposed id against the log.

Trigger
A defect is found in an approved spec, or a code fix contradicts spec text.
Context
Grep spec-error-log.md and every spec folder for the next free id in the owning spec's range — never read the 313 KB log whole. Entry format, back-prop obligation at approval, and the rule that a proposed id is a suggestion to re-verify, not a reservation.
Evidence
161 unique ERR-NNN-NNN ids filed; the collision class is documented in CLAUDE.md as an M-severity finding repeated three times.

.claude/skills/calibration-pass/

Measure, ladder, land, lock

The most distinctive workflow in this repo and the most repeated — and it carries hard-won rules that are expensive to rediscover.

Trigger
Any "the engine's X is unrealistic" task: goal rate, foul rate, shot volume, keeper contacts.
Context
Build an env-gated diagnostic first (TD_*_DIAGNOSTIC=1); measure a baseline over full matches on fixed seeds; sweep the [GT] ladder; an offline sweep gives the shape, never the value — take the landing value from a live run; re-measure; lock with a scenario whose pre-fix failure is verified by execution in a worktree at the pre-fix commit, not inferred.
Evidence
8 distinct TD_* diagnostic instruments; 41 recorded full-gate runs; the foul pass measured 37.5 fouls/90 at the value its offline sweep recommended.

.claude/skills/spec-promote/

Supplement to 11-file spec set

Ten specs were promoted in a single wave, each to an identical structure, each needing the same registry and prefix bookkeeping.

Trigger
A converged docs/tracking/*-design.md is being promoted, or a new spec number is being reserved.
Context
The 11-file layout; FR- prefix allocation checked against every existing prefix (the proposed FR-PR- once collided with Pressing AI's); SPEC_INDEX.md row added before the folder; back-props filed atomically at approval; sign-off is a human authority and is not self-grantable.
Evidence
52 of 56 design supplements carry AR cycles; 53 specs in the registry, all approved.

Not everything repeated should be a skill. The full dotnet gate runs the same way 41 times over — that is a script (tools/gate.sh: install SDK, run suite, assert the quarantine file is empty), referenced from a skill rather than described in one. The distinction matters: skills carry judgement, scripts carry keystrokes.

Question two

Improving what exists

Four findings about the skills, scripts and workflows already in play.

High The repo had no project skills at all

Before this pass there was no .claude/ directory. Ten global skills were available; none of them knew anything about this project. So 161 ERR filings, 41 gate runs, 281 AR-1 rounds and 58 landing rituals were each re-derived from a 97.6k-token rules file, every time, by reading prose. That is the single largest source of both token spend and convention drift here — and it is why the four cards above matter more than any individual prompt fix.

Medium adversarial-review doesn't know this repo's obligations 281 AR-1 rounds

The global skill terminates when a full pass surfaces no new High or Medium findings. The repo's convention — used across 52 design docs — is that an L-only round closes the cycle, which is compatible but differently stated. The real gap is what the global skill cannot know: that a finding against approved spec text obliges an ERR- filing and a back-prop, and that this repo's most expensive lesson is verify by execution, not by inference. Add a project-scoped adversarial-review that defers to the global skill for method and adds the repo's filing obligations and the execution rule.

Question four

Lessons worth carrying

Drawn from the repo's own record. The first six are Soccer Manager Pro's; the last three generalize to any simulation game. Each ends with the rule it implies.

  1. SMP-1

    A test suite can prove the composition runs and never ask whether it works

    Every match was 0–0 for months. The ball's velocity was identically zero for entire 90-minute matches, possession was never granted, and 321 match-engine tests passed throughout. The capstone asserted tick count, cadence, finiteness, bounds and digest advance — all true of a match in which nothing happens.

    Rule Every composition root needs one acceptance test that asserts the outcome the system exists to produce. "It ticks without throwing" is not that test.
  2. SMP-2

    The measurement keeps refuting its own brief

    Three times the named lever was the wrong one. The foul rate was framed as a threshold to tune; the threshold turned out to be a cliff, not a dial. "Save quality" was framed as a low number; it was undefined, because the keeper made zero contacts. The keeper pass then tripled contacts and moved goals by nothing at all.

    Rule Instrument before fixing, and budget for the diagnosis being wrong. A pass that refutes its own brief is a success, not a failure — but only if it was built to measure rather than to confirm.
  3. SMP-3

    Fixes break instruments, and instrument breakage looks like mechanism breakage

    The keeper-contact pass passed its own gate, then failed on two test instruments and a third in CI — none of them defects in the landed mechanisms. Post-strike touches became common enough to break a sampler that read velocity at end-of-tick; a shifted first restart broke a non-vacuity guard; a shifted possession onset broke a liveness window.

    Rule When a change moves event frequency or timing, re-validate every test whose sampling window or non-vacuity guard assumes the old distribution — before running the full gate, not after it goes red.
  4. SMP-4

    Symmetric systems need mirrored examples

    Three home/away asymmetry defects shipped in the Decision Tree because every spec worked example and every fixture used the home team. Away sides consumed a home-perspective zone map for months.

    Rule Any team-relative geometry gets a mirrored test. If the spec has a worked example, it gets a mirrored worked example too.
  5. SMP-5

    "Approved" stopped meaning "exists"

    53 specs approved; 22 of them have no src/ assembly. For 42% of the registry, approval status says nothing about whether code exists — which is exactly the proxy a reader reaches for.

    Rule Track "has a consumer" as a separate column from "approved", and put it where the approval status is read.
  6. SMP-6

    Code that has never compiled is not code

    Six spec test suites and one production assembly had never compiled — for months — so every claim of the form "the suite enforces X" was unverifiable. A Linux compile/test gate over the whole tree found eight such surfaces in its first run, and 30 genuine failures in the first execution of 1,165 tests.

    Rule Compile the entire tree on every push, from day one. This one is already fixed here — keep it, and never let a suite be quarantined in a way that can grow.
  7. GEN-1

    A playable build asks the only question a spec cannot

    Specs answer "is this correct?". Only a build answers "is this any good?". Reaching a playable match surfaced a goal rate roughly ten times football's and a home/away asymmetry around fifty times a real home advantage — both invisible while the work was specification.

    Rule Get to a playable slice early and keep it playable, even when the slice is embarrassing. It is the only instrument that measures fun.
  8. GEN-2

    Spec-ahead-of-code is a ratio to manage, not a virtue to maximize

    Specify-before-code demonstrably works here — the defect classes found are design defects caught in review rather than bugs found in production. But the frontier ran to 42% unimplemented, and every unimplemented spec is a design decision that has not yet met contact with a compiler.

    Rule Cap the ratio. When approved-without-consumer passes a threshold you set in advance, the next work item is implementation, not another spec.
  9. GEN-3

    Determinism discipline is cheap up front and expensive to retrofit

    Domain tags, subsystem ordinals, draw-site allocation and canonical serialization order all had to be right before anything drew a random number. The places where that discipline was applied late are exactly where the structural errors were filed.

    Rule In any simulation intended to replay, save, or go multiplayer, fix the RNG stream layout and serialization order before the first draw site ships — not when the second one needs it.

Four additions

quiet-by-default

A monitor that mostly says nothing

Every finding on this page is gated on a threshold in the analyzer, and a run that trips nothing prints an empty list. That is deliberate: a dashboard with something to say every day teaches its reader to stop looking. The thresholds are in one dictionary at the top of chat-review.py — raise them when a finding stops being worth acting on.

repeat-shape detection

Skill candidates that find themselves

The analyzer normalizes each prompt — stripping ids, numbers, filenames and ERR codes — and clusters the shapes. Three or more of the same shape emits a skill candidate with the real prompts as evidence. That closes the loop: you never have to notice the repetition yourself, which is the part humans are worst at.

gate-cost tracking

What a full gate run actually costs

Not built yet, and worth it: the analyzer already parses per-turn usage, so tagging the turns that run the dotnet gate would give a cost-per-gate-run figure. With 41 recorded runs and a suite that has grown from 1,165 tests, that number decides whether the gate belongs on every push or on a pre-landing checkpoint.

decision log

The one thing transcripts lose

Sessions record what was done, never what was considered and rejected — and this project's most valuable artifacts are exactly those: the rejected ends-swap, the refused third live-stats accumulator, the Option-B outline killed as unsound. A three-line rejected-alternatives note per landing would preserve the reasoning that the header chain currently buries in prose.
