## Candidate implementation now present

- `tools/run-tests-local.sh` is the versioned local/CI policy entry point; PR CI invokes `bash tools/run-tests-local.sh --pr` rather than bypassing it.
- `tools/checklist-auditor.py` and `tools/spec5-schema-auditor.py` now exist. Routine pre-commit/PR/nightly composition runs them **survey-only**, so pre-existing corpus debt cannot become an unrelated merge blocker.
- PR CI wires blocking auditor enforcement to the canonical approval event. `tools/testing-strategy-approval-scope.py` compares base/head `docs/specs/SPEC_INDEX.md` registry states and validates each newly approved registry folder against the candidate head tree. A non-approved/missing → `APPROVED` transition invokes `tools/run-testing-strategy-approval-audit.sh`, which reruns both auditors blocking for that spec directory. Missing base history, an unreadable/unparseable registry, or a nonexistent/invalid registry folder fails closed.
- The blocking approval walk is part of the repository's **required `Spec hygiene checks` CI context**. The non-required Linux functional job also exercises the same PR policy path, but a failing approval audit can no longer be bypassed merely because that functional context is not required by the live ruleset.
- approval status comes from `SPEC_INDEX.md`, whose own contract says it overrides individual spec-file status. Local status parsing remains only an isolated-fixture fallback and accepts established blockquoted/backticked/decorative APPROVED forms.
- checklist evidence is not accepted merely because a path or section exists: table rows and Markdown checkbox rows are both audited; an enforced approval scope with no checklist or no auditable checklist rows blocks; cited sections are sliced to their actual Markdown blocks and must contain concrete claim-bearing text/values; explicit numeric/literal values are mandatory complete-token matches (`60` does not match `600`); named programmatic checks require an explicit `--captured-check` attestation.
- the §5 schema auditor validates Appendix-C-shaped payloads rather than keyword presence. An enforced approval scope with no §5 test-plan file blocks. §5.1 requires all five taxonomy rows — Unit, Integration, Simulation, Determinism (integer or em dash), and End-to-end / soak — in addition to property/tier/owner, scenario/manifest/tier with resolving paths, coverage targets, determinism field/tier/source, approval linkage to actual parsed §9 rows, and version history.
- the last completed survey measurement before the checkbox/status/complete-taxonomy hardening was **548 findings** (219 checklist + 329 §5 schema) on the `edf6d4b` candidate. The hardened auditors are stricter, so that figure is retained only as a historical lower-bound planning input; A3.4 must remeasure the current corpus rather than reusing 548 as a current count.
- `.githooks/pre-commit` evaluates the staged Git index in a persistent `.git/testing-strategy/precommit-snapshot`. Bootstrap pays the one-time full materialization outside the normal 60-second acceptance measurement. Later runs compare the previous/current index tree, remove deleted tracked paths with a linear manifest `comm`, and refresh only changed index paths. Unchanged tracked files retain their mtimes while untracked generated/bin/obj outputs survive. `generate_projects.py` also avoids rewriting byte-identical generated project/solution files, preserving MSBuild incremental state.
- snapshot materialization sets `GIT_LFS_SKIP_SMUDGE=1` and locally disables both LFS process/smudge execution plus the LFS-required flag. The hook needs staged index/pointer bytes, not binary asset payloads, so unavailable/unfetched LFS objects cannot reject a commit before the tests run.
- pre-commit selection is declared in `tools/dotnet-ci/precommit.runsettings` with NUnit method-name-prefix rules (`^int_`, `^sim_`, `^e2e_`) rather than unsafe `FullyQualifiedName` substring exclusions. Ordinary unit names containing `Point_`, `Fingerprint_`, `MalformedInt_`, or `QuickSim_` remain eligible.
- the normal pre-commit attempt has an enforced 60-second whole-composition failure bound and uses one incremental generated-solution `dotnet test` invocation rather than 34 cold sequential project invocations. `--fast` is valid without a test filter.
- D2 is pinned to FsCheck.NUnit 2.16.6 in the candidate tooling surface.
- D3 collector selection is pinned to coverlet.collector 6.0.4 in the candidate tooling surface; the separate per-tier threshold mapper/auditor remains open.
- `sim_match_engine_close_chance` remains owner-held RED, not quarantine. The PR composition selects it by exact test `Name`, executes it separately, and requires one unambiguous failed result with the recorded `-0.165 / 0.407` diagnostics, no extra results, and the expected runner exit. Drift, ambiguity, abnormal execution, or unexpected green blocks.
- `.github/workflows/nightly.yml` separates GitHub-hosted Linux functional/simulation/soak execution from authoritative Spec #16 certification. The self-hosted Windows/Unity job is disabled unless repository variable `DETERMINISM_CERTIFIED_RUNNER_ENABLED=true`; until then a GitHub-hosted notice records the operational gap rather than queueing indefinitely for an unregistered runner.

Approval-transition enforcement now lives inside required `Spec hygiene checks`; neither Linux functional-job name itself is required.
