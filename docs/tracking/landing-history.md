## Why this file exists

`CLAUDE.md`'s OPEN ISSUES section states its own contract: *"the titles here are an index, not the
record."* It had stopped being one. Measured on August 22, 2026 the section was **80,461 of the
file's 104,292 bytes (77%)**, and six bullets — the ones reproduced below — were **72,711 of those
bytes (70% of the whole file)**; one bullet alone, #29/#41, was **38.6%**. Every agent working in this
repository is instructed to *"read this file completely before every task"*, so that weight is paid on
every task, whether or not the task touches any of it.

The convention that made this hard to fix is real and is **not** relaxed here: this project preserves
historical rows verbatim and forbids editing them. So nothing was edited. The text was **moved**, and
this file is where it moved to — the same convention, a different file, no text destroyed. `CLAUDE.md`
keeps one index paragraph per item, pointing here.

**This file confers no status.** It is not a spec, not a registry, and not a decision record. It says
nothing about whether an item is open or closed:

- **`docs/tracking/open-issues.md` remains the owning record** for every live blocker, and
  `open-issues-resolved.md` for closed ones. Read those before acting on anything.
- **`docs/tracking/CHANGELOG.md` remains the `Last Updated` entry chain.**
- **`docs/tracking/spec-error-log.md` remains the authority on every `ERR-` id** named below.

Where a narrative here disagrees with one of those files, **they win** — a moved narrative is frozen
at the moment of its move, exactly like the pre-promotion design supplements described in
`CLAUDE.md`'s DESIGN SUPPLEMENT note.
